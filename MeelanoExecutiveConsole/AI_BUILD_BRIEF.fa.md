# بریف ساخت هوش مصنوعی: MEELANO، کنسول مدیران

## هدف محصول
برنامهٔ دسکتاپ فارسی و راست‌به‌چپ برای مشاهدهٔ چک‌های دریافتی/پرداختی، فروش و جریان نقدی. دامنهٔ فعلی شامل چک و فروش است؛ ERP، حسابداری عمومی، انبار و حقوق‌ودستمزد جزو آن نیستند.

## پشته و ساختار
- .NET 8، WPF و C#؛ UI در `MeelanoExecutiveConsole`، مدل/محاسبه/سرویس SQL در `MeelanoExecutiveConsole.Core` و Specs خوداجرا در `MeelanoExecutiveConsole.Specs`.
- رابط فارسی RTL با تم تیرهٔ گرافیتی/سبزآبی و تم روشن لوکسِ عاجی/طلایی؛ انتخاب تم در داشبورد و ویزارد SQL یکپارچه و در `%LOCALAPPDATA%\MEELANO\theme.txt` ماندگار است. تاریخ شمسی، مبلغ تومان، پنجرهٔ قابل تغییر اندازه و DPI-aware.
- SQL driver: `Microsoft.Data.SqlClient`; TCP مستقیم به IP/DNS و پورت قابل‌تنظیم، پیش‌فرض 5050. رمزگذاری فعال است، اما اعتبارسنجی گواهی غیرفعال است؛ فقط برای شبکه و دادهٔ آزمایشی ایزوله، نه محیط عملیاتی.
- نصب‌کنندهٔ per-user ویندوز x64 با Inno Setup 6؛ build self-contained single-file. WPF فقط در Windows اجرا می‌شود.
- `Version` فایل `.csproj` منبع مرجع version/setup/release است.

## اتصال و ورود داده
- SQL Login هنگام اجرا (بدون ذخیره رمز) یا Windows Authentication؛ هیچ نام‌کاربری/رمز/connection string/host در سورس، ZIP، EXE یا تنظیم محلی قرار ندهید.
- ابتدا دیتابیس‌های قابل‌دسترسی و metadata جدول/View کشف می‌شوند. نگاشت ستون‌های لازم چک/فروش و مقادیر هر نوع/وضعیت را کاربر صریحاً تأیید می‌کند؛ هیچ SQL نامحدود یا نام ستون حدسی اجرا نمی‌شود.
- سرویس فقط metadata و `SELECT` اجرا می‌کند و snapshot در حافظه می‌سازد. `ApplicationIntent=ReadOnly` صرفاً routing hint است؛ مالک DB باید مجوز واقعی را روی login با SELECT/CONNECT محدود کند.
- SQL DATE/DATETIME نوع‌دار Gregorian به شمسی نمایش داده می‌شود؛ متن Jalali استاندارد سال 1300–1499 نیز parse می‌شود و قالب مبهم رد می‌شود. واحد منبع چک و مبلغ/سود فروش باید جداگانه و صریح تومان یا ریال انتخاب شود؛ پیش‌فرض حدسی ندارد، تبدیل ریال ÷10 است و مبلغ/سود فروش یک ضریب مشترک دارند.
- عملیات import با progress stage/row count، لغو، اعتبارسنجی سخت‌گیرانه و سقف 250,000 ردیف برای هر جدول/View انجام می‌شود. شکست import دادهٔ فعلی dashboard را جایگزین نمی‌کند.
- اطلاعات SQL فقط در حافظه و فقط‌خواندنی است؛ تغییر وضعیت مالی غیرفعال و refresh با اتصال دوباره انجام می‌شود.

## محدودیت‌های مهم
- منبع فعلی پروژه کد login/role یا API اصلی آتیران را ندارد؛ اتصال مستقیم نقش‌های آن برنامه را اعمال نمی‌کند. فقط مجوز SQL همان login ملاک است.
- جدول جداگانهٔ طرف‌حساب در UI کنونی وجود ندارد؛ مشتری/تأمین‌کننده از فیلدهای چک/فروش نمایش داده می‌شود.
- جمع و رتبه‌بندی فروش روی snapshot واردشده است؛ نمودار روزانه به ۹۰ روز اخیر محدود می‌شود تا تعداد عناصر WPF کنترل شود.
- رادار از چک‌های در انتظار و ماندهٔ آغازین صفر ساخته می‌شود؛ ماندهٔ واقعی بانکی نیست.
- سرور مقصد/schema/حساب read-only از این workspace قابل دسترسی نیست؛ mapping و اتصال مقصد باید روی شبکهٔ مقصد تأیید شود.
- نصب‌کننده unsigned است و ممکن است SmartScreen هشدار دهد.

## کیفیت و راستی‌آزمایی
- Specs: `dotnet run --project .\MeelanoExecutiveConsole.Specs\MeelanoExecutiveConsole.Specs.csproj --configuration Release`.
- Windows workflow: restore/build/test، publish self-contained، ساخت Setup، نصب بی‌صدا و smoke test اجرای برنامهٔ نصب‌شده را انجام می‌دهد.
- آزمون CI جای تست واقعی TLS، مجوز و mapping مقصد، DPI/چاپگر و تأیید گزارش مالی را نمی‌گیرد.

## اصول ایمنی
حساب read-only جداگانه و least-privilege، VPN/private network، فایروال محدود و TLS معتبر استفاده کنید؛ هیچ SQL port را عمومی نکنید. رمز مدیریتی یا مشترک را در client پخش نکنید. برای roleها/API آتیران باید قرارداد/منبع مجاز فراهم باشد. SQL write فقط پس از طراحی مجوز، audit، تراکنش و بازیابی.
