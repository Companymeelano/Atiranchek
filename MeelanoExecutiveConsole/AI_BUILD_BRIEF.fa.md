# بریف ساخت هوش مصنوعی: MEELANO، کنسول مدیران

## هدف محصول
برنامهٔ دسکتاپ فارسی و راست‌به‌چپ برای مشاهدهٔ نمونه‌ای چک‌های دریافتی/پرداختی، فروش و جریان نقدی. دامنهٔ این build فقط همین بخش‌ها است؛ ERP، حسابداری عمومی، انبار و حقوق‌ودستمزد جزو آن نیستند.

## پشته و ساختار
- .NET 8، WPF و C#؛ UI در `MeelanoExecutiveConsole`، منطق مستقل در `MeelanoExecutiveConsole.Core` و تست خوداجرا در `MeelanoExecutiveConsole.Specs`.
- UI تیرهٔ گرافیتی/سبزآبی با جزئیات طلایی، فارسی RTL، نمایش ارقام فارسی، پنجرهٔ قابل تغییر اندازه و aware از DPI.
- Setup per-user ویندوز x64 با Inno Setup 6؛ build self-contained single-file برای x64 یا ARM64. WPF اجرا در Windows می‌خواهد.
- `Version` در فایل `.csproj` مرجع نسخه است؛ workflow نسخه را به Setup می‌دهد و Release را از همان مقدار نام‌گذاری می‌کند.

## رفتار پیاده‌شده
- داشبورد فروش روز، ورودی/خروجی و خالص هفت روز (امروز + شش روز)، هشدار و سررسید نمونه.
- مرکز چک: جست‌وجوی فارسی/عربی و رقم‌های فارسی/عربی، فیلتر، چندانتخابی، جمع انتخاب و تاریخ وزنی.
- انتقال وضعیت در FinanceService با کنترل نوع چک و مراحل معتبر.
- فروش نمونه، خروجی CSV، چاپ جدولی، رادار ۳۰روزه و جابه‌جایی سناریویی فقط برای چک‌های دریافتی انتخاب‌شده.
- تعهدهای معوق در روز اول رادار تجمیع می‌شوند؛ ماندهٔ آغازین صفر است.
- CSV با quoting، newline، عددهای خام برای ستون‌های عددی و محافظت از سلول متنی فرمول‌پذیر.
- خطاهای UI/فرایند ثبت می‌شوند؛ لاگ چرخش ۱ مگابایتی دارد.

## وضعیت و محدودیت‌ها
- تمام داده‌ها ساختگی و درون‌حافظه‌ای‌اند؛ با بستن برنامه پاک می‌شوند.
- اتصال SQL Server آتیران، schema/query، احراز هویت، مجوز، audit و persistence پیاده‌سازی نشده است.
- امتیاز ریسک نمونه ثابت است؛ رادار، ماندهٔ بانکی واقعی نیست.
- نسخهٔ 1.0.2 نصب‌کنندهٔ unsigned دارد؛ ممکن است SmartScreen هشدار ناشر ناشناس دهد.

## کیفیت و راستی‌آزمایی
- از ریشهٔ مخزن تست منطق: `dotnet run --project .\MeelanoExecutiveConsole.Specs\MeelanoExecutiveConsole.Specs.csproj --configuration Release`.
- Workflow ویندوزی Specs، build، publish self-contained، ساخت Setup، نصب بی‌صدا و اجرای ۱۰ثانیه‌ای برنامهٔ نصب‌شده را پیش از انتشار عمومی انجام می‌دهد.
- کپی کردن فایل‌های `bin/obj` قدیمی جایگزین build نیست. در انتشار، artifact نصب‌کننده از build و smoke test همان workflow می‌آید.
- آزمون CI جای آزمون دستی در چند رزولوشن/DPI، چاپ، Windows SmartScreen و تأیید دادهٔ واقعی را نمی‌گیرد.

## اصول ایمنی محصول واقعی
هیچ connection string، رمز، token یا schema فرضی را در سورس نگذارید. ابتدا قرارداد داده را از مالک سامانه بگیرید و read-only با دسترسی کمینه شروع کنید. نوشتن مالی فقط با هویت، مجوز، تأیید صریح، تراکنش، audit و backup/restore آزموده مجاز است.
