# گزارش ممیزی و اتصال SQL Server — MEELANO Executive Console 1.1.0

**دامنه:** بازبینی Core، ViewModel، WPF/XAML، خروجی CSV/چاپ، تنظیمات اتصال، کشف schema، واردسازی، فرمت تومان/شمسی، ساخت و نصب Windows.

## تغییرات نسخهٔ 1.1.0

| حوزه | تغییر | کنترل ایمنی/دقت |
|---|---|---|
| نقطهٔ اتصال | ورودی IP/DNS و پورت ثابت TCP؛ پیش‌فرض 5050 و امکان 1433 | host جدا از پورت اعتبارسنجی می‌شود؛ connection string از ورودی کاربر ساخته می‌شود. |
| احراز هویت | SQL Login هنگام اجرا یا Windows Authentication | هیچ username/password/connection string/IP در سورس، تنظیم محلی یا EXE hardcode/persist نمی‌شود؛ PasswordBox هنگام بستن پاک می‌شود. |
| رمزنگاری | SQL Client با Encrypt فعال و TrustServerCertificate خاموش | TLS certificate validation الزامی است؛ گواهی نامعتبر دور زده نمی‌شود. پورت عمومی باز توصیه نمی‌شود. |
| فهرست دیتابیس | نمایش پایگاه‌های ONLINE قابل‌دسترسی پس از ورود | query روی `sys.databases` است؛ دیتابیس system مخفی است و `HAS_DBACCESS` بررسی می‌شود. |
| کشف schema | کشف جدول/View و ستون‌های قابل‌مشاهده از INFORMATION_SCHEMA | مرحلهٔ کشف فقط metadata می‌خواند، نه ردیف‌های تجاری. |

| واردسازی | فقط ستون‌های انتخاب‌شده از منبع خوانده و در snapshot حافظه ذخیره می‌شوند | queryها فقط SELECT هستند، شناسه‌ها از metadata می‌آیند و bracket-escape می‌شوند؛ هیچ UPDATE/INSERT/DELETE وجود ندارد. سقف 250,000 ردیف برای هر منبع. |
| بارگذاری | overlay با درصد مرحله و شمار واقعی ردیف‌های خوانده‌شده | count پیش از خواندن انجام می‌شود؛ overlay درصد جعلیِ مبتنی بر زمان نشان نمی‌دهد؛ cancel و timeout دارد. صحنهٔ مرکزی با WPF Viewport3D، کره و حلقه‌های نورانی متحرک ساخته می‌شود. |
| حالت زنده | داده‌های SQL فقط‌خواندنی و فقط در حافظه | انتقال وضعیت در داشبورد برای SQL غیرفعال است؛ اتصال مجدد برای تازه‌سازی لازم است؛ شکست import دادهٔ فعلی را جایگزین نمی‌کند. |
| پول/تقویم | واحد منبع برای چک و مبلغ/سود فروش صریحاً تومان یا ریال انتخاب می‌شود؛ خروجی همیشه تومان است | SQL DATE/DATETIME میلادی داخلی به شمسی نمایش داده می‌شود؛ متن شمسی YYYY/MM/DD در بازهٔ 1300–1499 پشتیبانی می‌شود؛ تاریخ مبهم/نامعتبر رد می‌شود. |
| ریسک | ستون ریسک اختیاری | در نبود مقدار، امتیاز «—» است و وارد هشدار ریسک نمی‌شود. |
| CSV/چاپ | مبلغ با برچسب تومان، تاریخ شمسی | فرمول‌سازی spreadsheet همچنان برای سلول متن محافظت می‌شود؛ خروجی CSV UTF-8 BOM دارد. |
| نسخه | Version پروژه مرجع Setup و Release شد | نسخه به 1.1.0 ارتقا یافت؛ workflow قبل از انتشار Specs، build، install و startup smoke test را اجرا می‌کند. |

## یافته‌های امنیتی و محدودهٔ اختیار
1. **اعتبارنامهٔ مدیریتی که در گفتگو فرستاده شد افشاشده تلقی شود و باید rotate شود.** داخل EXE گذاشتن یا default کردن آن رد شد؛ فایل self-contained قابل مهندسی معکوس است.
2. برنامهٔ این مخزن **کد ورود/نقش‌های اصلی آتیران را ندارد**؛ فقط داشبورد نمونه وجود داشت. در اتصال مستقیم، مجوز SQL همان login ملاک است و نقش‌های کاربران آتیران بازتولید نمی‌شوند. اگر آن نقش‌ها ضروری‌اند، منبع/API یا قرارداد احراز هویت و ماتریس نقش غیرمحرمانه لازم است.
3. `ApplicationIntent=ReadOnly` به‌تنهایی مرز مجوز نیست؛ مالک SQL باید حساب جداگانه را در سطح دیتابیس/View فقط به CONNECT/SELECT محدود کند. سرویس کلاینت به‌صورت برنامه‌نویسی فقط metadata و SELECT دارد.
4. مقصد، schema واقعی، TLS certificate و حساب read-only در workspace ارائه نشده‌اند؛ اتصال واقعی مقصد از CI قابل دسترسی/تأیید نیست. نگاشت باید با مالک مالی/DBA تأیید شود.
5. پورت forward شدهٔ SQL را در اینترنت عمومی در دسترس نگذارید؛ VPN، firewall allowlist و certificate معتبر لازم‌اند.

## اعتبارسنجی
- **نتیجهٔ محلی:** محیط این عامل Windows/WPF و .NET SDK ندارد؛ build محلی انجام نشده است.
- **نتایج خودکار:** در انتظار Windows CI همین commit؛ اجرای موفق در این گزارش تا مشاهدهٔ run ادعا نمی‌شود.
- Specsهای افزوده‌شده: نمایش تومان/شمسی، parse سخت‌گیرانهٔ تاریخ SQL/Jalali و رد تاریخ مبهم، اعتبارسنجی host/port، فقط‌خواندنی‌بودن snapshot و نمودار روزانهٔ ۹۰ روز اخیر. این Specs تا اجرای CI تأییدشده محسوب نمی‌شوند.
- موارد دستی باقی‌مانده حتی پس از CI: اتصال شبکهٔ واقعی، TLS CN/SAN و firewall/forwarding، فهرست مجوزدار دیتابیس‌ها، صحت انتخاب schema/ستون/واحد، reconcile مبلغ/تاریخ با منبع، DPI، چاپگر و SmartScreen.

## محدودیت‌های محصول
- اتصال یک snapshot درون‌حافظه‌ای است؛ persistence، refresh دوره‌ای، audit تغییرات و ارسال وضعیت مالی به SQL پیاده نشده‌اند.
- موجودی آغازین صفر است و رادار ماندهٔ بانکی نیست. دادهٔ نمونه برای offline fallback و demonstration باقی است.
- در UI فعلی موجودیت جداگانهٔ مشتری/تأمین‌کننده وجود ندارد؛ طرف‌حساب از فیلدهای چک/فروش می‌آید.
- Setup unsigned است؛ برای استقرار سازمانی code-signing، سیاست به‌روزرسانی و تست نصب لازم است.
