# MEELANO | کنسول مدیران

نسخهٔ **1.1.6**؛ داشبورد مدیریتی دسکتاپ فارسی و راست‌به‌چپ با پوستهٔ گرافیتی/سبزآبی و جزئیات طلایی، به‌همراه تم روشن لوکسِ عاجی/طلایی. تم از نوار بالای داشبورد یا پنجرهٔ اتصال SQL قابل تغییر است و انتخاب در `%LOCALAPPDATA%\MEELANO\theme.txt` ذخیره می‌شود. در شروع، پنجره بیشینه باز می‌شود؛ `F11` یا `Esc` حالت پنجره را تغییر می‌دهد. رابط قابل تغییر اندازه است و ناحیه‌های بلند پیمایش می‌شوند.

## اتصال مستقیم SQL Server
از دکمهٔ **اتصال SQL** وارد شوید و پایگاه داده را انتخاب کنید. برنامه بلافاصله ساختار را تحلیل و گزارش‌های چک و فروش را بدون انتخاب دستی جدول یا ستون بارگذاری می‌کند. این قابلیت فقط برای قرارداد نماهای گزارش زیر است؛ schema واقعی آتیران در این مخزن موجود نیست و شناسایی عمومی همهٔ دیتابیس‌ها یا معنای ستون‌های مالی از روی اسم تضمین‌شدنی نیست. اگر قرارداد موجود نباشد یا ناسازگار باشد، برنامه به‌جای حدس‌زدن خطا نشان می‌دهد و دادهٔ فعلی را حفظ می‌کند.

### قرارداد لازم برای بارگذاری خودکار
مدیر پایگاه داده باید دو **VIEW** یکتا با نام‌های `MEELANO_Checks` و `MEELANO_Sales` در schema قابل‌مشاهده ایجاد کند و با توجه به معنای واقعی داده‌های مقصد، نگاشت و محاسبات این نماها را تأیید کند. برنامه هیچ نمایی را ایجاد یا تغییری در سرور اعمال نمی‌کند. حساب برنامه باید دسترسی metadata و SELECT هر دو نما را داشته باشد. نام‌ها نسبت به حروف بزرگ/کوچک حساس نیستند؛ اگر نام نما در چند schema تکرار شود یا به‌جای View جدول باشد، بارگذاری رد می‌شود.

| نما | ستون‌های اجباری |
|---|---|
| `MEELANO_Checks` | `CheckNumber`, `CheckKind`, `PartyName`, `DueDate`, `CheckStatus` و دقیقاً یکی از `AmountToman` یا `AmountRial` |
| `MEELANO_Sales` | `SaleDate`, `CustomerName`, `SellerName` و یا جفت `AmountToman`/`ProfitToman` یا جفت `AmountRial`/`ProfitRial` |

ستون‌های اختیاری چک `BankName` و `RiskScore` (عدد صحیح ۰ تا ۱۰۰) و ستون اختیاری فروش `CollectionStatus` هستند. شماره/نوع/وضعیت و نام اشخاص باید SQL text، تاریخ‌ها SQL `date`/`datetime`/`datetime2`/`smalldatetime` میلادی و مبالغ عددی دقیق (`decimal`, `numeric`, `money`, اعداد صحیح) باشند؛ float و متن تاریخ پذیرفته نمی‌شوند. نوع چک فقط `دریافتی`/`پرداختی` یا `incoming`/`receivable`/`outgoing`/`payable` و وضعیت فقط `در انتظار`, `وصول‌شده`, `پرداخت‌شده`, `برگشتی`, `معلق` یا به‌ترتیب `pending`, `collected`, `paid`, `returned`, `suspended` است. مقادیر عددی، NULL، مبهم و ناشناخته حدس زده نمی‌شوند. مبلغ ریال به تومان تقسیم بر ۱۰ می‌شود؛ مبلغ و سود فروش باید هم‌واحد باشند. نماهای خالی مجازند. دادهٔ نامعتبر، رکورد تکراری چک یا مقدارهای ناشناخته باعث توقف کل بارگذاری می‌شود.

- جستجوی شبکه با انتخاب آداپتور و درخواست کاربر انجام می‌شود؛ حداکثر محدودهٔ /24 پیرامون IP داخلی همان آداپتور و پورت‌های ۱۴۳۳، ۵۰۵۰ و پورت واردشده بررسی می‌شوند. پاسخ TDS بدون ارسال رمز بررسی می‌شود، اما نتیجه احراز هویت سرور نیست. جستجو برای شبکه‌های مجاز است و ممکن است به‌دلیل فایروال، پورت متفاوت، SQL Browser غیرفعال، VPN، زیرشبکهٔ دیگر یا پاسخ ندادن، سروری را پیدا نکند. ورود دستی همچنان موجود است. IP عمومی یا سرورهای خارج از این محدوده به‌طور خودکار کشف نمی‌شوند.
- احراز هویت SQL Login با ورود نام کاربری/رمز در همان اجرا یا Windows Authentication.
- **فقط برای آزمایش:** رمزگذاری اتصال فعال است، اما با `TrustServerCertificate=true` هویت سرور و اعتبار گواهی بررسی نمی‌شود و نیازی به ورود یا تنظیم گواهی نیست. این اتصال در برابر جعل سرور و حملهٔ مرد میانی آسیب‌پذیر است؛ فقط در شبکهٔ آزمایشی ایزوله با داده و حساب آزمایشی از آن استفاده کنید، نه اینترنت یا محیط عملیاتی.
- برنامه فقط queryهای metadata و `SELECT` اجرا می‌کند. داده پس از اعتبارسنجی در حافظه بارگذاری می‌شود؛ هیچ `INSERT`، `UPDATE` یا `DELETE` اجرا نمی‌شود و تغییر وضعیت برای دادهٔ SQL غیرفعال است.
- رمز، IP، connection string و پروفایل اتصال در سورس، EXE و تنظیمات محلی ذخیره نمی‌شوند. ورود SQL در پایان پنجره پاک می‌شود.
- تاریخ‌های SQL میلادی در رابط به شمسی تبدیل می‌شوند؛ تاریخ نامعتبر باعث توقف بارگذاری می‌شود.
- سقف محافظتی بارگذاری هر جدول/View برابر ۲۵۰٬۰۰۰ ردیف است. برای حجم بالاتر، View گزارش محدودشده انتخاب کنید.
- صفحهٔ بارگذاری سه‌بعدی درصد مرحله/ردیف‌های خوانده‌شده را نشان می‌دهد. تا پایان اعتبارسنجی، دادهٔ فعلی برنامه جایگزین نمی‌شود.

> **امنیت و مجوزها:** حسابی با حداقل دسترسی و فقط `SELECT` روی Viewهای گزارش استفاده کنید؛ پورت SQL را به اینترنت عمومی باز نگذارید و دسترسی شبکه را با VPN و فایروال محدود کنید. این پروژه کد ورود/نقش‌های برنامهٔ اصلی آتیران را ندارد؛ در اتصال مستقیم، مجوز SQL همان حساب ملاک است و مجوزهای کاربری آتیران بازتولید نمی‌شوند. برای پیاده‌سازی نقش‌های آن برنامه، منبع/API یا قرارداد احراز هویت و ماتریس نقش‌های غیرمحرمانه لازم است.
>
> **اعتبارنامهٔ افشاشده را تعویض کنید.** هیچ رمز مدیریتی را داخل برنامه یا فایل توزیع قرار ندهید؛ EXE تک‌فایلی نیز قابل مهندسی معکوس است. برای هر اجرا حساب جداگانهٔ read-only توصیه می‌شود.

## داده و محدودیت‌ها
- اگر اتصال برقرار نشود یا لغو شود، برنامه روی داده‌های ساختگی `DemoRepository` می‌ماند و نشانگر منبع «محیط نمونه» را نمایش می‌دهد.
- دادهٔ SQL پس از بارگذاری فقط در حافظه است؛ همگام‌سازی زنده یا ذخیره‌سازی محلی ندارد. برای تازه‌سازی، دوباره اتصال بگیرید.
- قرارداد نماها باید با مالک دیتابیس تأیید شود: نوع و وضعیت چک، معنای مبلغ، تاریخ، سود، فروشنده/مشتری و مقیاس امتیاز ریسک. در نبود ستون ریسک، امتیاز به‌صورت «—» نمایش داده می‌شود و در هشدار ریسک وارد نمی‌شود.
- برنامهٔ موجود بخش مجزای فهرست مشتری/تأمین‌کننده ندارد؛ طرف‌حساب‌ها از ستون‌های نگاشت‌شدهٔ چک/فروش نمایش داده می‌شوند.
- رادار نقدینگی فقط چک‌های در انتظار و ماندهٔ آغازین صفر را محاسبه می‌کند؛ ماندهٔ بانکی یا پیش‌بینی رسمی نیست.
- اتصال واقعی به سرور مقصد از CI قابل آزمایش نیست. آدرس سرور و schema در این مخزن ارائه نشده؛ پیش از استفادهٔ عملی، روی شبکه و حساب read-only مقصد آزمون پذیرش انجام دهید.

## نصب و امنیت Windows
نصب‌کنندهٔ per-user برای Windows 10 نسخهٔ 1809 (build 17763) و جدیدتر یا Windows 11 x64 است و Administrator لازم ندارد. برنامه self-contained است و نصب جداگانهٔ .NET Runtime نیاز ندارد. نصب‌کننده و برنامه امضای دیجیتال ندارند؛ ممکن است SmartScreen هشدار ناشر ناشناس نشان دهد.

## ساخت و آزمون در Windows
پیش‌نیاز: .NET 8 SDK و برای Setup، Inno Setup 6:

```powershell
.\MeelanoExecutiveConsole\Build-Windows.ps1 -Installer
```

آزمون‌های Core/نگاشت و تاریخ شمسی:

```powershell
dotnet run --project .\MeelanoExecutiveConsole.Specs\MeelanoExecutiveConsole.Specs.csproj --configuration Release
```

خروجی‌ها:

```text
MeelanoExecutiveConsole\artifacts\win-x64\MeelanoExecutiveConsole.exe
MeelanoExecutiveConsole\artifacts\installer\MEELANO-Executive-Console-Setup-win-x64.exe
```

WPF فقط روی Windows اجرا می‌شود. CI ساخت، آزمون، نصب و smoke test را انجام می‌دهد؛ آزمون واقعی شبکه/TLS، مجوزهای دیتابیس، mapping مقصد، چاپگر و DPI دستگاه کاربر همچنان دستی است.

## قابلیت‌های داشبورد
- **تحلیل سررسید خزانه:** چک‌های در انتظار بر اساس سررسیدگذشته (۱–۳۰، ۳۱–۶۰، ۶۱–۹۰ و بیش از ۹۰ روز)، امروز، ۱–۷، ۸–۳۰ و بیش از ۳۰ روز آینده دسته‌بندی می‌شوند. تعداد، جمع دریافتی، جمع پرداختی و تفاضل هر دسته و خروجی CSV قابل مشاهده است. چک برگشتی جداگانه نمایش داده می‌شود و معلق/تسویه‌شده در دسته‌های انتظار نیستند.
- نسبت پوشش = مجموع چک‌های دریافتی در انتظار ÷ مجموع پرداختی‌های در انتظار × ۱۰۰؛ از تمام سررسیدگذشته‌ها تا روز ۳۰ آینده شامل هر دو انتها. اگر پرداختی صفر باشد نسبت «—» است. این نسبت تضمین وصول یا موجودی بانکی نیست و فقط بر اساس snapshot چک محاسبه می‌شود.
- تم تیره و روشن با کنترل انتخاب، فوکوس صفحه‌کلید و افزایش کنتراست جدول‌ها؛ آیکن‌های برداری برجستهٔ اختصاصی برای بخش‌های اصلی.
- فروش امروز، ورودی/خروجی هفت‌روزه، سررسیدها و رادار ۳۰روزه.
- مرکز چک با فیلتر/جست‌وجوی فارسی و رقم‌های فارسی/عربی، چندانتخابی، CSV امن و چاپ جدولی.
- جمع و رتبه‌بندی روی کل snapshot، نمودار تجمیعی روزانهٔ ۹۰ روز اخیر، مبلغ به تومان و محاسبهٔ تاریخ وزنی.
- سناریوی جابه‌جایی سررسید چک دریافتی انتخاب‌شده؛ فقط برای دادهٔ نمونه اعمال می‌شود.
- ارقام فارسی و تاریخ شمسی در رابط؛ خروجی CSV با UTF-8 BOM و محافظت در برابر فرمول صفحه‌گسترده.

## خطا و پشتیبانی
خطاهای سراسری اجرا در `%LOCALAPPDATA%\MEELANO\Logs\startup.log` ثبت می‌شوند؛ رمز و connection string در این لاگ ثبت نمی‌شوند. خطاهای SQL به پیام‌های بدون نمایش اعتبارنامه تبدیل می‌شوند. در گزارش مشکل، نام جدول/مقدارهای PII، IP خصوصی، رمز یا connection string را ارسال نکنید.

## ساختار پروژه
- `MeelanoExecutiveConsole` — رابط WPF، پنجرهٔ اتصال/نگاشت و نصب‌کننده.
- `MeelanoExecutiveConsole.Core` — محاسبات مالی، فرمت شمسی، CSV و سرویس فقط‌خواندنی SQL Server.
- `MeelanoExecutiveConsole.Specs` — آزمون‌های خوداجرا برای مرزهای محاسبات، CSV، جست‌وجو، نگاشت و تقویم.
- `.github/workflows/build-windows.yml` — restore/build/test، نصب/اجرای smoke test و انتشار نسخه پس از موفقیت CI.
